## 单账号单地登录（会话版本号）

源码中 `users` 表含 **`auth_revision`**：每次成功登录或注销会递增，JWT 内携带 `arv`（与库中值一致才有效）。异地再次登录会使旧 token 立即失效，返回 `401` 并提示「会话已在其它地点登录或已注销」。**已有数据库**需手工执行：

```sql
ALTER TABLE users ADD COLUMN auth_revision BIGINT NOT NULL DEFAULT 0;
```

迁移后请所有用户**重新登录**，旧 JWT 无 `arv` 声明将视为无效。

前端对带 `X-Token` 的请求遇 `401` 会清空登录态并切换到登录页；关闭标签页会通过 `sendBeacon` 尽力调用 `POST /api/auth/logout-beacon`。

同一账号在同一房间仅保留 **一条** `/ws/game` 连接：新开页面连接会关闭旧连接（WebSocket close code `4000`）。玩家在战场持续发送输入时，服务端会节流感知 `auth_revision`，若已在其它地点登录导致 JWT 失效，会关闭连接（close code `4001`）。

## 房主离开与房间关闭

- **房主**调用 `POST /api/rooms/{roomId}/leave`（或在大厅点击「退出登录」前会先离开房间）时：房间立即标为 `EXPIRED`、清空 `room_players`、关闭房内全部 WebSocket，效果与原「解散」一致。
- **普通成员**离开房间仅移除本人在 `room_players` 中的记录。
- 房间内事件 `ROOM_EXPIRED` 的 `payload.reason`：`OWNER_LEFT`（房主离开或注销导致关闭）、`STALE_TIMEOUT`（超时自动解散）。

若旧库中仍存在未使用的 `player_stats` 表，可在 MySQL 中执行 `DROP TABLE IF EXISTS player_stats;` 删除。

## `rooms` 表与增量结构不一致时

源码中的 [`schema.sql`](../air-combat-backend/src/main/resources/schema.sql) 里 `rooms` **仅保留**：`name`、`owner_user_id`、`status`、`red_count`、`blue_count`、`created_at`。若在 MySQL Workbench / 图形工具里仍能看到已废弃字段（例如 `winner`、`started_at`、`finished_at`），说明当前库是按旧结构建的，与服务端 **`Room.java` / `RoomMapper` 不一致**，会出现启动或查询异常。

推荐做法：

1. **一次性重建（课程演示推荐）**：执行 [`db/recreate_mysql8.sql`](../air-combat-backend/src/main/resources/db/recreate_mysql8.sql) 清空相关表后，再依次执行当前的 `schema.sql` 与 `data.sql`。步骤见该脚本注释。
2. **仅裁剪列（不想清库时可试）**：`ALTER TABLE rooms DROP COLUMN winner, DROP COLUMN started_at, DROP COLUMN finished_at;`（列名不存在则跳过对应语句）。
3. 重建或手工初始化完成后，可考虑将 `spring.sql.init.mode` 设为 `never`，避免无意间反复执行 `data.sql`。

## 联机开始对局（房主点击后）

- 后端先通过 WebSocket 广播 `MATCH_COUNTDOWN`（3 秒），再真正初始化战场并广播 `BATTLE_STARTED`。
- 房间内玩家应在等待界面保持 WebSocket 连接（进入房间后自动连接），以便同步倒计时并自动进入战场。
